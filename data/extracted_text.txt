1. Background and Motivation 
Machine-learned malware classifiers routinely score above 0.99 F1 in static, 
cross-validated evaluations, yet post-deployment performance can degrade by as much 
as 50% within months. This is not a symptom of poor tuning — it is concept drift: 
attackers continuously mutate code, adopt new packers, and change delivery 
infrastructure, so the statistical relationship between a binary's features and its true 
label shifts over time. Standard k-fold evaluation hides this problem entirely, because 
randomly splitting a chronologically evolving dataset leaks future malware variants into 
training, producing an illusion of robustness that the TESSERACT framework 
(Pendlebury et al., 2019) exposed as a pervasive spatio-temporal bias in the field. 
Two existing tools fall short of fixing this. Static classifiers (Random Forests, XGBoost, 
MLPs) freeze a decision boundary at training time and have no mechanism for tracking 
how malware clusters migrate through feature space. Discrete sequence models 
(RNNs, LSTMs, GRUs) add some temporal awareness but assume fixed, regularly 
spaced time steps — an assumption malware sampling violates constantly, since a 
threat actor may release a dozen variants in a week, then go quiet for months. Neither 
approach represents drift as what it actually is: a continuous process happening 
between observations. 
This project proposes to model malware evolution directly as a continuous-time 
dynamical system using a Latent Neural ODE. This reframes drift-resilient detection 

----- PAGE 2 -----
from a periodic-retraining problem into a forecasting problem: instead of a boundary 
that goes stale, the model learns the rules governing how the boundary moves. As a 
secondary extension — pursued only once the core model is validated and stable — we 
plan to test whether augmenting it with a discrete jump mechanism improves handling 
of sudden, discontinuous shifts (e.g., a zero-day disclosure or a geopolitical shock). 
This project is scoped in two explicit tiers throughout: a core deliverable we are 
committing to, and a stretch extension we will attempt if time and stability allow. 
2. Clearly Defined Problem Statement 
1.​ Core: Build and rigorously evaluate a Latent Neural ODE classifier for Windows 
PE malware that models concept drift as a continuous vector field, and 
demonstrate — under strict chronological (TESSERACT-style) evaluation — that it 
degrades significantly less over time than static baselines, while remaining 
trainable on a single consumer-grade GPU. 
2.​ Stretch: If the core model is stable, extend it with a discrete jump network and 
evaluate whether it improves classification stability through an abrupt-drift 
window, compared to the non-jump Latent ODE.

1. The Real-World Problem: Concept Drift in the 
Malware Landscape 
The Adversarial Arms Race and Classifier Degradation 
The deployment of machine learning within cybersecurity has historically been characterized 
by an ongoing and highly asymmetric adversarial arms race. Security vendors deploy 
high-capacity models—ranging from gradient-boosted decision trees to deep neural 
networks—trained on massive corpora of benign and malicious Portable Executable (PE) files. 
In controlled, static evaluations, these models routinely achieve classification accuracy and F1 
scores exceeding 0.991. However, post-deployment performance inevitably undergoes a 
catastrophic degradation, sometimes dropping by as much as 50% in realistic longitudinal 
evaluations3. 
This degradation is not a symptom of algorithmic instability, inadequate model capacity, or 
poor hyperparameter tuning; rather, it is a direct consequence of the adversary's continuous 
evolution. Attackers deliberately mutate source code, adopt novel packing algorithms, alter 
structural metadata, implement reflective loading, and utilize polymorphic engines to evade 
detection5. Consequently, the statistical relationship between the extracted features of a 
binary and its true label changes over time. This phenomenon is formally defined in machine 
learning literature as concept drift, presenting one of the most significant barriers to 
sustainable, automated threat detection5.

Evaluation Biases and the Illusion of Solved Problems 
The impact of concept drift has been systematically understated in historical cybersecurity 
literature due to pervasive experimental biases. Research utilizing the TESSERACT evaluation 
framework highlights that standard k-fold cross-validation inherently leaks future knowledge 
into the training phase4. Because malware families evolve chronologically, randomly sampling a 

----- PAGE 3 -----
dataset to create training and testing splits virtually guarantees that future variants of a 
malware family will be included in the training data. This temporal bias artificially inflates model 
performance, giving a false impression of robustness3. 
Furthermore, spatial bias occurs when the base rate of malware to benign software in the 
testing dataset does not reflect real-world deployment conditions1. When the strict 
spatio-temporal constraints defined by TESSERACT are rigorously enforced, the true 
vulnerability of static models to concept drift becomes glaringly apparent12. This exposes the 
massive financial and operational costs associated with continually retraining production 
models, which currently require analysts to manually label drifting samples to update static 
boundaries9. 
To quantify this degradation objectively, the Area Under Time (AUT) metric provides a definitive 
measure of robustness. Based on the trapezoidal rule, AUT captures a classifier's robustness to 
time decay by integrating the Area Under the Receiver Operating Characteristic (AUROC) over 
a sequence of future temporal testing blocks4. The failure of current models to maintain a 
stable AUT score necessitates a paradigm shift in how temporal adversarial dynamics are 
modeled. 
2. Limitations of Prevailing Detection Architectures 
The Static Classifier Trap 
Traditional machine learning paradigms, including Random Forests, XGBoost, LightGBM, and 
standard Multilayer Perceptrons (MLPs), learn a frozen decision boundary during the training 
phase. These models operate under the implicit assumption that the topological relationship 
between malicious and benign clusters in the high-dimensional feature space will remain 
constant indefinitely. 
When applied to a temporally shifting landscape, static models fail because they lack an 
internal mechanism to account for the trajectory of adversarial evasion. If a model is trained on 
data from a specific eight-month temporal window, the decision boundary is optimized 
exclusively for the feature distributions present within that timeframe. By the twelfth month, 
virtual and real drift will have caused the malware clusters to migrate to entirely new regions of 
the feature space4. The static classifier, completely oblivious to this migration, continues to 
apply the obsolete decision boundary. This results in a surge of false negatives as novel 
malware evades detection, and a corresponding spike in false positives as benign software 
adopts structural features previously correlated with malware. 
The Inadequacies of Discrete Sequence Models 
To incorporate temporal awareness, sequence models such as Recurrent Neural Networks 
(RNNs), Long Short-Term Memory networks (LSTMs), and Gated Recurrent Units (GRUs) have 
been frequently proposed. While highly effective in domains with regularly sampled time 
series—such as audio processing, natural language, or financial tick data—these discrete-time 
models exhibit critical vulnerabilities when applied to malware concept drift16. 
The primary inadequacy stems from the assumption of fixed time steps. Standard RNNs 
assume that observations arrive at uniform, discrete intervals. However, malware evolution and 
sample collection are highly irregular. A specific threat actor might release dozens of variants of 

----- PAGE 4 -----
a trojan within a single week during an active campaign, followed by months of silence before 
launching a newly obfuscated variant16. Discrete sequence models cannot naturally encode the 
variable elapsed time between these observations without resorting to artificial binning or 
time-delta concatenation, both of which severely degrade representational fidelity18.

Shifting from Discrete Boundaries to Continuous Vector Fields

(Neural ODEs). First formalized by Chen et al. (2018), Neural ODEs replace the discrete 
sequence of hidden layers in a deep neural network with a continuous formulation, 
parameterizing the derivative of the hidden state using a neural network20.

Ensuring Theoretical Validity: The Necessity of Neural Jump ODEs 
(NJODEs) 
While standard Neural ODEs excel at modeling smooth, continuous trajectories, relying 
exclusively on a continuous framework is theoretically insufficient for the realities of 
cybersecurity. Concept drift in malware is characterized by a combination of continuous 
gradual drift (e.g., polymorphic iteration) and sudden step-drift (e.g., the rapid exploitation of a 
newly disclosed zero-day vulnerability, or a sudden change in global geopolitical events 
dictating new attacker objectives)24. 
Because ODE trajectories cannot cross each other and are mathematically bound by the 
Picard-Lindelöf theorem, standard Neural ODEs struggle to model sudden, discontinuous 
jumps in the state space18. An ODE assumes the evolution of features is a smooth 
homeomorphism, which breaks down when a completely novel malware family appears 
instantaneously in the wild. Therefore, to ensure the proposed solution is valid, the architecture 
must be augmented from a standard Latent ODE to a Neural Jump Ordinary Differential 
Equation (NJODE) framework25. 
NJODEs are continuous-time hybrid models that alternate between continuous flows 
(governed by the Neural ODE) and instantaneous state updates (jumps) triggered by specific 
stochastic events25. This allows the model to capture the smooth evolution of an existing 
malware family while simultaneously accommodating the abrupt emergence of a completely 
novel feature distribution. 
In the NJODE framework, continuous evolution is maintained between observations. However,

Statistical Profile and Structural Feature Space 
The BODMAS dataset contains 134,435 samples—comprising 57,293 malware and 77,142 benign 
PE files—collected over a contiguous 14-month window from August 2019 to September 
202033. The explicit timestamp associated with each sample permits the precise modeling of 
continuous-time evolution necessary for ODE integration. 
Each sample is represented as a pre-extracted 2381-dimensional numeric feature vector. These 
vectors are generated using the LIEF (Library to Instrument Executable Formats) framework, 
which parses the structural integrity of the Windows Portable Executable format. The 2381 
features encompass multiple orthogonal views of the binary, rendering the dataset highly 
robust for analyzing complex feature drift31: 
●​ PE Header Metadata: Metrics regarding the number of sections, entry point 
coordinates, and file alignment configurations. 
●​ Sectional Entropy: The statistical entropy of distinct PE sections (e.g., .text, .data). This is 
vital for drift modeling, as the continuous adoption of novel cryptographic packers by 
adversaries heavily influences entropy distributions. 
●​ Import Address Table (IAT): Statistical summaries of the imported DLLs and specific API 
calls (e.g., kernel32.dll, ws2_32.dll), which reflect ongoing changes in the functional 
capabilities and payloads of the evolving malware. 
●​ Byte-Level Histograms: Raw statistical distributions of the compiled byte code, offering 
a low-level view of polymorphic mutations that occur over time31. 
The Natural Experiment of COVID-19 Concept Drift 
The 14-month span of the BODMAS dataset encapsulates one of the most significant periods 
of cyber-adversarial adaptation in modern history. The first half of the dataset (August 2019 to 
February 2020) establishes a pre-pandemic baseline of malware tactics, dominated by 
standard variants of Emotet and various banking trojans33. 
However, beginning in March 2020, the onset of the global COVID-19 pandemic catalyzed a 
massive, documented shift in malware tactics, generating a surge of novel phishing lures, 
healthcare-targeted ransomware, and entirely new delivery infrastructures. This provides an 
unprecedented natural experiment for evaluating concept drift. The suddenness of this 
transition is exactly why the proposed upgrade to Neural Jump ODEs is theoretically necessary; 
the continuous vector field models the gradual drift of existing families, while the discrete jump 
mechanism immediately accommodates the discontinuous emergence of pandemic-themed 
payloads without fracturing the ODE solver24. 
Comparative Baselines: EMBER and SOREL-20M 
While datasets like EMBER (2018) and SOREL-20M provide massive scale—with SOREL 
containing 20 million samples—they lack the rigorous, dense temporal granularity required for 
high-fidelity ODE integration35. TESSERACT evaluations on Android datasets have proven that 
scale alone does not mitigate the effects of concept drift if the temporal evaluation windows 
are not strictly enforced12. BODMAS, explicitly designed to highlight temporal family evolution, 
serves as the superior empirical foundation for proving the efficacy of continuous-time 
dynamics.

6. Experimental Protocol and Rigorous Evaluation 
Framework 
An optimal theoretical model is only as verifiable as its experimental methodology. To prevent 
the spatial and temporal biases outlined by the TESSERACT framework3, the experimental 
protocol enforces strict chronological partitioning, ensuring that the model is never exposed to 
future feature distributions during the training phase. 
Sequential Train-Validation-Test Splitting 
The dataset is partitioned chronologically based on the precise monthly timestamps inherent 
to BODMAS to simulate realistic deployment conditions37: 
●​ Training Set (Months 0–7): August 2019 through March 2020. This allows the model to 
learn the baseline vector field and the initial shocks of the early pandemic drift. 
●​ Validation Set (Months 8–9): April 2020 through May 2020. This near-future data is 
strictly used for hyperparameter tuning, early stopping, and calibrating the ODE solver 
tolerances (e.g., setting the rtol and atol thresholds). Under no circumstances is the 
model's performance on this set conflated with final testing.

To systematically prove the superiority of continuous-time dynamics in combating malware

performance ceiling of non-temporal modeling. The observed decay in Area Under the

exact magnitude of the concept drift present in the data2. 
Experiment 2: NJODE Temporal Integration 
The Neural Jump ODE model is trained on the exact same Months 0–7 data. Because the 
architecture actively learns the drift trajectory as a physical dynamic system, its evaluation on 
Months 10–13 should exhibit a significantly attenuated performance drop compared to the 
static baselines.

against continuous time (Months 8 through 13), a visual and statistical narrative is established. 
While static baselines will display a steep negative slope indicating performance decay, a 
successful NJODE will maintain a near-flat trajectory, definitively proving drift resilience over an 
extended operational horizon4.

7. Identifying and Mitigating Systemic Risks in ODE 
Training 
While the theoretical foundation of Neural ODEs is mathematically elegant, their practical 
deployment on highly non-stationary datasets introduces distinct engineering risks, particularly 
regarding numerical stability and computational overhead. Overcoming these limitations is 
necessary for a robust, deployable cybersecurity solution. 
The NFE Explosion and Stiff ODEs 
The most prominent systemic risk in continuous-time deep learning is the explosion of the 
Number of Function Evaluations (NFE). As the model trains, the continuous flow it attempts to 
map often becomes highly complex, contorted, and nonlinear as it tries to separate increasingly 
sophisticated malware samples from benign software. When an ordinary differential equation 
exhibits widely varying timescales—where certain latent components change rapidly while 
others remain stable—the system is mathematically classified as a Stiff ODE39. 
Standard adaptive explicit solvers, such as the widely utilized dopri5, struggle severely with 
stiffness. To maintain numerical stability and satisfy predefined error tolerances, the explicit 
solver is forced to take infinitesimally small step sizes. This causes the NFE to skyrocket 
exponentially26. The resulting NFE explosion leads to drastically increased training times, 
creates massive latency during inference, and can ultimately cause backpropagation via the 
adjoint method to fail due to accumulated numerical rounding errors43. 
To mitigate this critical bottleneck, the research protocol must dynamically monitor stiffness. If 
stiffness is encountered during training on the BODMAS dataset, the architecture must 
transition from explicit solvers to single-step implicit schemes. Implicit methods provide a 
vastly superior framework for handling stiff dynamics without fracturing the step size, allowing 
the neural ODE to accurately learn stiff systems without succumbing to stability collapse39. 
Furthermore, implementing kinetic or Jacobian regularization techniques can heavily penalize 
highly contorted vector fields, forcing the model to learn smoother, more easily integrated 

----- PAGE 11 -----
dynamics that keep NFE manageable without sacrificing predictive power27. 
Alternative Generative Approaches: Continuous Normalizing Flows 
(CNFs) 
If the discriminative Latent NJODE model struggles to capture the sheer diversity of virtual drift 
across the 2381-dimensional structural feature space, the methodology can pivot toward 
modeling the exact probability density function of the malware features using Continuous 
Normalizing Flows (CNFs)45. 
CNFs construct an exact, invertible mapping between a simple base distribution (e.g., a 
standard Gaussian) and the highly complex, non-stationary data distribution of the drifting 
malware21. By leveraging the instantaneous change of variables formula—which elegantly 
requires only the trace of the Jacobian rather than the computationally prohibitive 
determinant—CNFs can track the exact likelihood of a malware sample over continuous time18. 
Recent advances in flow matching bypass the need for log-density evaluation at every solver 
step, training the network directly via regression to analytically prescribed velocity fields. This 
dramatically accelerates training and provides non-asymptotic convergence bounds46. While 
computationally heavier than a standard classifier, CNFs utilizing modern flow-matching 
techniques offer an incredibly rigorous fallback strategy for modeling severe concept drift with 
exact likelihood quantification45. 
8. Foundational Literature and Future Research 
Directions 
The architecture defined in this report represents a novel synthesis that exists at the precise 
intersection of three distinct, cutting-edge domains: continuous-time deep learning, rigorous 
spatio-temporal cybersecurity evaluation, and longitudinal malware dataset benchmarking. 
The mathematical foundation rests heavily upon the introduction of Neural ODEs by Chen et al. 
(2018), which revolutionized the application of continuous-depth networks and the adjoint 
sensitivity method20. This continuous paradigm was subsequently adapted for irregularly 
sampled time series via Latent ODEs by Rubanova et al. (2019)19. However, the specific 
vulnerability of pure ODEs to sudden, discontinuous state changes necessitated the integration 
of Neural Jump ODEs (NJODEs), introduced by Herrera et al. (2020), providing the critical 
mathematical machinery to handle sudden malware step-drift efficiently17. 
Simultaneously, the experimental rigor demanded by this architecture is entirely derived from 
the TESSERACT framework formulated by Pendlebury et al. (2019)2. Prior to TESSERACT, the 
cybersecurity community fundamentally misunderstood the severity of concept drift due to 
pervasive spatial and temporal experimental biases. The introduction of time-aware splits and 
the Area Under Time (AUT) metric forces models to prove genuine predictive capability against 
future data4. Finally, the execution of this experiment relies entirely on the BODMAS dataset 
compiled by Yang et al. (2021), which provides the densely timestamped, realistic malware 
vectors necessary for ODE integration24. 
Prior literature has predominantly addressed malware concept drift via active learning and 
discrete retraining loops—periodically labeling new, anomalous samples and updating the static 

----- PAGE 12 -----
decision boundary manually5. Similarly, while continuous-time networks like Latent ODEs and 
NJODEs have seen vast success in healthcare time-series analysis and optimal financial 
filtering25, their application to the high-dimensional structural features of drifting malware 
represents a largely unexplored frontier. 
Future research directions must focus on expanding the continuous-time framework to 
graph-structured data. Malware execution traces can be naturally represented as Control Flow 
Graphs (CFGs) or API call graphs. Integrating continuous dynamics with Graph Neural 
Networks (GNNs) could allow the ODE to model not just the drift of structural features, but the 
actual evolution of malicious behavioral execution paths over time10. 
9. Conclusions and Strategic Implications 
The pervasive phenomenon of concept drift dictates that static machine learning models 
deployed in cybersecurity environments are inherently depreciating assets. As adversaries 
continuously mutate code, leverage new packing engines, and adapt to global events, the 
static decision boundaries protecting network infrastructure rapidly become obsolete, 
necessitating costly manual retraining and leaving critical operational windows vulnerable to 
novel threats. 
By upgrading the static detection paradigm to a Neural Jump Ordinary Differential Equation 
architecture, this framework ceases to view malware as static points scattered in a vacuum. 
Instead, it correctly interprets adversarial evolution as a fluid, dynamic physical system—a 
continuous vector field punctuated by rapid, stochastic jumps triggered by novel exploit kits or 
geopolitical shifts. 
The integration of the BODMAS dataset ensures that the model is trained on realistic, densely 
timestamped adversarial behavior, while the strict adherence to the TESSERACT evaluation 
framework guarantees that the model's resilience to drift is mathematically validated against 
strict temporal gaps. Furthermore, by identifying and preparing for the risks associated with 
stiff ODEs and the NFE explosion, the architecture maintains computational feasibility for 
real-world deployment. 
If validated according to the rigorous metrics proposed herein, the capability to mathematically 
forecast the trajectory of adversarial evolution will fundamentally alter the defensive posture of 
the cybersecurity industry. It transitions automated threat detection from an endless, reactive 
patching cycle into a proactive, predictive science, where the continuous evolution of the 
adversary is actively integrated into the fabric of the defensive model.

1. Problem Statement and Motivation 
Malware detection models trained with machine learning usually score above 99% accuracy when tested in the lab, 
but their performance drops sharply once deployed, sometimes by close to 50% within a few months. This happens 
because attackers keep changing their code, packers and delivery methods, so the relationship between a file's 
features and whether it is malicious keeps shifting. This is called concept drift. Most existing classifiers (Random 
Forest, XGBoost, MLPs) learn one fixed decision boundary and never update it, so they slowly become outdated. 
Even random-forest based classifiers cannot tell when or how the malware landscape is moving. This project tries to 
model that movement directly, using a continuous-time model (Neural ODE) that learns how malware features 
evolve over time, instead of freezing a boundary at one point in time. 
2. Project Objectives 
1. To design a Latent Neural ODE model that represents malware feature drift as a continuous process rather than a 
fixed decision boundary. 
2. To train and test the model using strict month-wise (chronological) data splits so that future malware samples 
never leak into training, unlike random k-fold splits. 
3. To measure how much the model's accuracy decays over time using the Area Under Time (AUT) metric, and 
compare this decay against static baseline models (XGBoost, LightGBM, MLP). 
4. To handle the class imbalance in the dataset (malware vs benign files) using Focal Loss so rare malware samples 
are not ignored during training. 
5. (Stretch goal, if time permits) To add a jump-update mechanism to the ODE so it can react to sudden, one-time 
drift events, such as the spike in malware activity seen around the COVID-19 period in the dataset.

4. Proposed Methodology 
Raw PE Features (2381-d) → Encoder (compress to latent state) → Neural ODE Solver (evolve latent state through time) → 
Decoder → Benign / Malicious Prediction 
Proposed Model / Architecture: Latent Neural ODE (encoder-solver-decoder pipeline). 
An encoder network first compresses the 2,381 raw features of a file into a smaller latent vector (around 64 
dimensions). Instead of feeding this into a normal classifier straight away, we treat this latent vector as the starting 
point of a differential equation and let a small neural network (the ODE function) describe how this state should 
keep changing as time moves forward. An ODE solver (Dormand-Prince / dopri5) then integrates this equation to 
project the file's latent representation forward to the time it needs to be classified at. A decoder (a simple MLP) then 
takes this evolved latent state and outputs whether the file is benign or malicious. 
Brief justification: A normal classifier only knows about the training months it saw. An RNN/LSTM also assumes fixed 
and evenly spaced time steps, but malware doesn't appear on a fixed schedule; sometimes there are ten variants in 
one week and then nothing for two months. A Neural ODE does not have this constraint since it works in continuous 
time and can be evaluated at any gap. To make backpropagation possible without running out of GPU memory, we 
use the adjoint sensitivity method, which keeps memory usage constant no matter how many integration steps the 
solver takes. This is what makes it possible to train this on a single consumer GPU instead of needing a cluster.
